## Что сделано в 1.0.0.12 (полная переработка поверх 0.0.6)
* Единая версия `src/version.h`. Makefile собирается (`make`), страница и картинки вшиваются `tools/embed.py` в `build/assets_gen.h`.
* Единственная копия: новая просит старую выйти через `/data/ps4hddtools/quit.flag`, ждёт порт до ~90 с. Кнопка «Выключить» (`POST /quit`).
* Пассивность: при старте только лог и уведомление. Диски и SMART читаются по `POST /api/refresh` (страница делает это при открытии). Опрос страницы только пока идёт задание.
* `src/engine.cpp`: одна операция за раз (refresh / bench / scan), поток присоединяется (`join`), не `detach`. Проверка: буфер 1 МиБ через `mmap`; дочитывание частичных ответов; ошибочный блок перечитывается по секторам (до 60 с на блок, дальше «приблизительно»); первые 100 плохих LBA; скорость и ETA по окну 30 с без времени паузы; диапазон «с/по ГБ»; гистограмма времени блоков (20/50/150/500 мс, ошибка); прерывание при трёх мёртвых блоках подряд с ENXIO/ENODEV.
* Защита от сна: `sceSystemServicePowerTick()` каждые ~5 с, пока идёт замер/проверка (в том числе на паузе). Линковка `-lSceSystemService`.
* `src/smart.cpp`: общий SAT16 (CDB для чтения SMART совпадает с подтверждённым на консоли), запасной SAT12, native ATA; IDENTIFY (модель, прошивка, серийный, ёмкость, rpm), SMART DATA, пороги (0xD1), RETURN STATUS (0xDA, через sense-дескриптор). Вердикт здоров/внимание/плохо (правила в `smart_assess`). Устройства SONY пропускаются без команд.
* `src/disks.cpp`: целые диски `da*`/`ada*`; сопоставление с `passN` по ёмкости (IDENTIFY·512 = размер диска), запасной вариант по единственности; метки USB0/EXT0 по `statfs` точек `/mnt/usbN`, `/mnt/extN`.
* HTTP (`src/http.cpp`): таймауты 5/10 с, не больше 8 клиентов, без CORS, все POST требуют заголовок `X-Requested-With: ps4hdd`, устройство принимается только из списка найденных (по id `da0`), лимиты на заголовок/тело.
* Страница `web/index.html`: тёмная, вкладки дисков справа от `title.png`, SMART слева, проверка справа (карта 500 ячеек, статистика, журнал), окно подтверждения с оценкой времени, ru/en (словарь внутри страницы), favicon из `Icon_512.png`.
* Удалено: `check.cpp` (проверка разделов), `scan.cpp`, `disk_scan.*`, `app_state.h`, `index_html.h`.

## Проверено на ПК (`tests/test_api.py`, ASAN+UBSAN, «диск» = файл)
SMART-разбор по образцам, вердикты, пороги, статус; пары диск↔pass; ошибки чтения (ровно 3 сектора, верные LBA); пауза/продолжить/стоп; диапазон; зависшие клиенты и лимит; 403 без заголовка; единственная копия; `/quit`; вызовы keep-awake. Сборка под консоль `orbis-clang++ -Wall -Wextra` без предупреждений.

## НЕ проверено на консоли (ждём лог от пользователя)
* Всё, что связано с веб-интерфейсом и проверкой поверхности на реальном диске.
* Сопоставление `da0` ↔ `pass1` по ёмкости, метки USB0/EXT0 (нужна реальная точка монтирования; проверить `statfs`).
* RETURN STATUS (0xDA) через SAT и разбор sense: если мост не вернёт дескриптор, статус остаётся «неизвестен» (на вердикт не влияет).
* Предотвращает ли `sceSystemServicePowerTick` сон на 13.52: в логе после проверки смотреть строки; если консоль всё же засыпает, пробовать `sceShellCoreUtilResetAutoPowerDownTimer`.
* Чтение `da0` через `open(O_RDONLY)` (в 0.0.6 тоже не проверялось), запасной вариант с `O_NONBLOCK` есть.
* Для чужих моделей хост-чтения/записи не пересчитываются (только ST2000LM007), остальные показываются сырыми.

## Второй лог (пользователь прислал от другого человека, версия 0.0.5)
* Внутренний SSD Apacer AS350 256GB подключён напрямую по SATA: `pass1` CAM `protocol=3` (ATA), vendor/product пустые, паспорт в `XPT_GDEV_TYPE.ident_data` (строки уже в нормальном порядке). SMART через `XPT_ATA_IO` (native) читался, контрольная сумма сошлась: 14 показателей, температура raw[0], часы 16565, F1 «Total Host Writes» без единицы (не пересчитываем).
* `pass0` SONY `PS-SYSTEM 420R` (protocol 2), `pass2` USB-корпус ANKEJE `USB3.0` (protocol 2) с диском 1 ТБ (`da1`, есть `da1s2`/`da1s5`). Для ATA-диска версия 1.0.0.12 берёт модель/ёмкость из `ident_data`, команду IDENTIFY не шлёт. Корпус без SAT показывается как «SMART недоступен» с названием моста; проверка поверхности доступна.
* Диски определяются без базы: имена в `/dev` (`da<N>`, `ada<N>`), размер через ioctl, SMART-устройство по ёмкости из паспорта.
